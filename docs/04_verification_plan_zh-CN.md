# Radix-2 Butterfly MVP：验证计划

## 1. 文档目的

本文档定义 Radix-2 Butterfly MVP 的功能验证目标、参考模型、测试环境、场景矩阵、判定标准、现有证据和剩余缺口。

验证工作的核心目标是证明：V0 组合数据通路与 V1 流水数据通路在遵守同一份定点规格时，对相同有效输入产生逐位一致的数值结果和分量级饱和标志；V1 还必须满足固定延迟、启动间隔、气泡传播和复位丢弃语义。

本文档不把仿真通过等同于形式证明，也不把当前向量数量等同于穷举覆盖。综合、时序和物理实现结果由 `05_synthesis_and_ppa_analysis.md` 记录。

## 2. 验证范围

### 2.1 验证对象

| 对象 | 主要职责 | 验证重点 |
|---|---|---|
| `sat_q15` | 宽位有符号整数饱和到 16 位 Q1.15 | 正负边界、边界内值、分量级饱和标志 |
| `rne_sat_q30_to_q15` | Q*.30 经 RNE 舍入并饱和到 Q1.15 | guard/sticky、ties-to-even、正负对称、舍入后饱和 |
| `butterfly_comb` | V0 组合 Butterfly | 四路输出、四路分量级饱和标志、组合确定性 |
| `butterfly_pipe` | V1 固定延迟流水 Butterfly | 与 V0 数值等价、2 周期核心延迟、II=1、气泡和复位 |
| 评估包装层 | 为物理比较建立共同寄存器边界 | 不改变数值语义；只用于综合和 PPA，不替代核心 RTL 验证 |

### 2.2 明确不在当前范围内的内容

- `ready`、背压和可暂停流水线；
- 完整 FFT 的存储、地址和级间调度；
- 多时钟域和异步复位；
- UVM 环境；
- FPGA 上板或硅后测试；
- 全输入空间穷举；
- 形式等价检查和形式属性证明；
- 基于真实工作负载活动文件的功耗验证。

## 3. 验证依据与优先级

若实现、模型和文档出现冲突，按以下顺序处理：

1. `01_design_intent.md` 决定功能边界和接口意图；
2. `02_fixed_point_spec.md` 决定数值、位宽、舍入和饱和行为；
3. `03_microarchitecture.md` 决定流水、有效位和复位时序；
4. Python 位精确模型实现上述数值契约；
5. SystemVerilog 测试平台比较 RTL 与模型生成的期望结果。

任何发现的冲突都必须先修改规格或实现，再重新生成向量并回归测试，不能通过放宽测试平台比较规则来掩盖。

## 4. 参考模型

### 4.1 模型原则

`model/fixed_point_model.py` 是无时序的位精确整数模型。模型只使用整数运算，所有公开输入和输出均为 16 位有符号 Q1.15 编码。

模型执行：

1. 计算 17 位意义下的 `A+B` 与 `A-B`；
2. 对 `Y0` 两个分量分别进行 Q1.15 饱和；
3. 计算四个实数乘积及 34 位意义下的复数乘加；
4. 对 `Y1` 两个分量先执行 round-to-nearest, ties-to-even，再执行饱和；
5. 分别输出 `sat_y0_re`、`sat_y0_im`、`sat_y1_re`、`sat_y1_im`；
6. 聚合标志仅由分量标志归约得到，不作为独立数值语义。

### 4.2 模型自检要求

- 所有输入必须位于有符号 16 位范围 `[-32768, 32767]`；
- 不允许使用浮点运算计算 Butterfly 主数据通路；
- 正负 ties-to-even 必须对称；
- 舍入必须发生在饱和之前；
- 复数乘加的数学结果必须满足规格规定的宽位范围断言；
- 随机向量必须使用固定种子以保证可复现。

## 5. 测试向量

### 5.1 公共向量集

V0 与 V1 使用同一份 CSV 数据集。默认生成配置包括：

| 类别 | 数量 | 目的 |
|---|---:|---|
| 定向向量 | 7 | 零值、直通、相等输入、正负饱和、极值和混合符号 |
| 旋转因子向量 | 64 | 使用量化单位圆系数覆盖不同象限和符号组合 |
| 固定种子随机向量 | 1000 | 扩展数据组合与分量级饱和覆盖 |
| 合计 | 1071 | V0/V1 公共数值回归集 |

默认随机种子为 `0xB077E2`。重新生成向量时必须保存生成命令、随机种子和字段格式。

### 5.2 CSV 契约

公共 CSV 应包含：

- 用例名；
- 六个输入分量；
- 四个期望输出分量；
- 两个兼容聚合饱和标志；
- 四个分量级饱和标志。

测试平台以四个分量标志作为主要接口检查，并独立验证聚合标志等于对应分量标志的归约或。

### 5.3 必须覆盖的数值场景

| 场景 | 期望检查 |
|---|---|
| 全零输入 | 四路输出和四路饱和标志均为零 |
| `A=B` | 差值和 `Y1` 为零，`Y0` 按规格处理 |
| `W` 的实部或虚部为零 | 复数乘法的符号和交叉项正确 |
| Q1.15 最大、最小编码 | 无隐式无符号解释或缩位回绕 |
| `Y0` 正饱和与负饱和 | 输出钳位到 32767 或 -32768，只有对应分量标志置位 |
| `Y1` 正饱和与负饱和 | 先舍入再比较宽位结果，不能先截位 |
| 小于半、正好一半、大于半 | RNE 进位条件正确 |
| ties-to-even 且保留最低位为偶/奇 | 一半情形分别不进位或进位 |
| 负数 ties-to-even | 绝对值舍入后恢复符号，与正数规则对称 |
| 四个分量不同饱和组合 | 分量级标志互不混淆，聚合标志正确归约 |

## 6. V0 验证环境

`tb/v0/tb_butterfly_comb.sv` 是文件驱动、自检查测试平台。

每个 CSV 用例执行以下步骤：

1. 驱动六个输入分量；
2. 等待组合逻辑稳定；
3. 比较四路输出；
4. 比较四个分量级饱和标志；
5. 比较由分量标志归约得到的两个兼容聚合标志；
6. 累计错误，并在回归结束时统一给出 PASS 或 FAIL。

判定要求：

- 使用四态严格比较，未知值不得被当作匹配；
- CSV 为空、字段数量不正确或无法解析时必须失败；
- 任一数值或标志不匹配都必须使回归失败；
- 至少执行一个向量，否则失败。

## 7. V1 验证环境

`tb/v1/tb_butterfly_pipe.sv` 使用与 V0 相同的 CSV 数值期望，并增加两槽 scoreboard 表示核心的 2 周期固定延迟。

### 7.1 延迟与有效位

若事务在上升沿 `t` 以 `valid_in=1` 被核心接受，则必须在上升沿 `t+2` 后观察到对应数据和 `valid_out=1`。

必须检查：

- `valid_out` 与对应事务严格对齐；
- 连续有效输入时，输出在流水填满后连续有效；
- II=1，即每周期都能接受一个新事务；
- 无效输入形成气泡并逐级传播，不压缩前后事务次序；
- 数据与旋转因子属于同一事务，不允许 `W` 错位。

### 7.2 气泡行为

当 `valid_out=0` 时：

- 四个饱和标志必须为零；
- 在出现首个有效输出后，四个数据输出保持最近一次有效值；
- 无效数据内容不参与功能判定，但不得导致后续有效事务错位。

公共向量流在每第 11 个有效向量之前插入一个气泡，以同时覆盖连续流和断流。

### 7.3 复位行为

复位是同步复位。必须检查：

- 复位上升沿清除所有流水有效位；
- 流水线中尚未完成的事务被丢弃，复位释放后不得产生对应有效输出；
- 复位期间 `valid_out=0`；
- 复位期间四个饱和标志为零；
- 数据寄存器不要求全部清零，但不得在无有效位时被当作事务使用；
- 复位释放后的第一个周期可以立即接受新事务；
- 复位前后的事务不能混合。

测试平台在两笔有效事务仍在流水线中时施加复位，并在释放后第一拍发送新事务，以检查丢弃和立即恢复语义。

## 8. 回归流程

建议的可复现顺序为：

1. 运行 Python 模型单元测试或最小自检；
2. 用固定参数生成公共 CSV；
3. 编译并运行 V0；
4. 编译并运行 V1；
5. 保存工具版本、命令和 PASS 摘要；
6. RTL、模型、规格或向量生成器发生变化后，重新执行全部步骤。

当前仿真基线使用 Verilator 5.032。测试平台不得依赖该版本不支持的 `$fscanf` scanset 格式；CSV 通过 `$fgets` 逐行读取并手工分离用例名，再扫描数值字段。以 `verilator` 开头的普通注释也应避免被误识别为工具指令。

## 9. 通过标准

### 9.1 功能通过

- V0 对全部 1071 个公共向量无数值或标志不匹配；
- V1 对全部 1071 个公共向量无数值或标志不匹配；
- 两版对相同输入得到相同输出和分量级标志；
- CSV 解析、文件路径和向量数量检查均通过。

### 9.2 时序语义通过

- V1 核心固定延迟为 2 个周期；
- 连续事务以 II=1 传输且顺序不变；
- 气泡按周期传播；
- 复位丢弃所有在途事务；
- 复位释放后第一拍可接受新事务；
- 无效输出拍的饱和标志为零，数据保持约定得到满足。

### 9.3 失败条件

以下任一情况都构成验证失败：

- 任一输出分量不匹配；
- 任一分量级或聚合饱和标志不匹配；
- `valid_out` 提前、延后或丢失；
- 事务顺序改变或旋转因子错位；
- 复位后出现被丢弃事务；
- 测试平台因空文件、解析错误或零向量而静默通过；
- 编译警告被配置为错误时仍存在未处理警告。

## 10. 当前验证证据

截至当前工程基线：

- 公共数据集包含 1071 个可复现向量；
- V0 回归报告 `PASS: 1071 vectors checked with no mismatches`；
- V1 使用同一数值数据集，并通过延迟、连续流、气泡、分量标志和复位检查；
- Verilator 5.032 的 timescale、未使用信号和 CSV scanset 兼容问题已清理；
- V0 与 V1 均通过通用 Yosys 综合检查，未推断锁存器；
- 两版均完成 Nangate45 映射及布局布线，证明 RTL 属于可综合子集。

这些证据支持当前回归范围内的功能正确性，但不构成全状态空间证明。

## 11. 剩余缺口与后续增强

| 缺口 | 风险 | 建议优先级 |
|---|---|---|
| 未统计代码、分支或翻转覆盖率 | 无法量化 RTL 结构覆盖程度 | 中 |
| 未建立独立的 RNE helper 单元测试回归 | 舍入正确性主要由系统向量间接覆盖 | 高 |
| 未进行形式等价检查 | V0/V1 的全输入数值等价未被证明 | 中 |
| 未进行门级仿真 | 复位、有效位和综合网表行为未动态复核 | 低 |
| 未注入 X/Z | 对未知值传播的鲁棒性未评估 | 低 |
| 功耗没有统一 VCD/SAIF | 当前功耗只能视为向量无关估算 | 高（若继续做功耗结论） |

MVP 可以在明确披露上述缺口的前提下完成。若项目继续演进为带背压和缓冲区的 Butterfly Engine，必须重新编写接口协议、停顿、满/空、drain 和完成状态的验证计划，不能直接沿用本文件宣称覆盖。
