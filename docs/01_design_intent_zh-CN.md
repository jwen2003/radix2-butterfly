# Radix-2 Butterfly MVP：设计意图

## 1. 文档目的

本文档定义 Radix-2 Butterfly 项目 MVP 的设计目标、功能边界、评价方法与初始假设。

本文档回答的是“为什么这样设计”以及“本轮工程闭环要证明什么”，不重复规定定点数值细节或具体实现参数。精确位宽、二进制小数点位置、舍入及溢出策略由 `02_fixed_point_spec.md` 定义；微架构由 `03_microarchitecture.md` 定义；验证方法和证据由 `04_verification_plan.md` 记录；综合、布局布线与 PPA 分析由 `05_synthesis_and_ppa_analysis.md` 记录。

## 2. 项目目标

本项目以一个 DIF Radix-2 复数 Butterfly 处理单元为载体，完整经历以下工程闭环：

```math
\text{设计意图}
\rightarrow
\text{定点模型}
\rightarrow
\text{RTL}
\rightarrow
\text{验证}
\rightarrow
\text{综合}
\rightarrow
\text{结果分析}
\rightarrow
\text{设计修改}
```

MVP 的首要成功标准不是实现尽可能高的最大时钟频率 `F_max`，而是得到一个：

- 功能正确；
- 行为明确；
- 可以综合；
- 可以复现；
- 可以比较；
- 设计选择能够用验证与综合证据解释；
- 能够根据反馈完成至少一次合理修改的处理单元。

较高的 `F_max` 是待观察和比较的指标之一，而不是必须最大化的唯一目标。高频设计可能以更多寄存器、更大资源占用、更高延迟、更多设计与验证复杂度，甚至更高功耗为代价。不同应用具有不同目标函数，因此本项目首先分析这些权衡，不预设最高频率方案一定是最佳方案，也不为追求极端频率而扩大 MVP。

## 3. 功能定义

MVP 实现一个 DIF Radix-2 复数 Butterfly：

```math
Y_0=A+B
```

```math
Y_1=(A-B)\times W
```

其中，`A`、`B` 和 `W` 为复数输入，`Y_0` 和 `Y_1` 为复数输出。`W` 表示外部提供的旋转因子。

将复数运算展开后：

```math
Y_{0,\mathrm{re}}=A_{\mathrm{re}}+B_{\mathrm{re}}
```

```math
Y_{0,\mathrm{im}}=A_{\mathrm{im}}+B_{\mathrm{im}}
```

```math
D_{\mathrm{re}}=A_{\mathrm{re}}-B_{\mathrm{re}}
```

```math
D_{\mathrm{im}}=A_{\mathrm{im}}-B_{\mathrm{im}}
```

```math
Y_{1,\mathrm{re}}
=D_{\mathrm{re}}W_{\mathrm{re}}
-D_{\mathrm{im}}W_{\mathrm{im}}
```

```math
Y_{1,\mathrm{im}}
=D_{\mathrm{re}}W_{\mathrm{im}}
+D_{\mathrm{im}}W_{\mathrm{re}}
```

在 RTL 接口中，复数将拆分为独立的实部与虚部信号。因此，数据接口包含六路实数输入：

- `a_re`
- `a_im`
- `b_re`
- `b_im`
- `w_re`
- `w_im`

以及四路实数输出：

- `y0_re`
- `y0_im`
- `y1_re`
- `y1_im`

每个输出分量同时具有独立的饱和标志：

- `sat_y0_re`
- `sat_y0_im`
- `sat_y1_re`
- `sat_y1_im`

核心接口不保存独立的聚合饱和状态。若上层只关心 `Y_0`、`Y_1` 或整个事务是否发生任意饱和，可在接口外对相应分量标志进行归约或。

所有数值均采用有符号定点表示。输入暂定为 16 位；精确格式及中间位宽由后续定点规格冻结。

## 4. 已冻结的设计决定

### 4.1 选择 DIF Radix-2

MVP 只实现一种明确的 Butterfly 数据流，不同时支持 DIT 与 DIF。

选择 DIF 后，计算顺序明确为：

1. 计算 `A+B` 和 `A-B`；
2. 将差值 `A-B` 与 `W` 相乘。

这一顺序提供了自然的算术边界。V1 据此冻结为三级寄存器结构：第一级完成加减并保存与差值对齐的旋转因子，第二级完成四路并行实数乘法，第三级完成乘积加减、舍入、饱和和输出寄存。该划分已经通过功能验证和开源 ASIC 实现流程评测，但仍只代表一个有效设计点，不宣称为全局最优结构。

选择 Radix-2 并不意味着它在所有 FFT 中优于 Radix-4。Radix-2 是仍然包含定点、复数乘法、流水与资源权衡的最小研究单元，适合在 2–4 周内完成闭环。

### 4.2 只实现独立 Butterfly 处理单元

MVP 不实现完整 FFT。完整 FFT 会同时引入级间数据调度、地址生成、存储组织、旋转因子索引和控制逻辑，使问题边界从算术数据通路扩展为完整系统。

本轮先隔离 Butterfly 处理单元，避免在出现错误或性能问题时无法区分根因来自：

- 数值表示；
- 算术 RTL；
- 流水控制；
- 存储；
- 地址生成；
- FFT 级间调度。

### 4.3 旋转因子由外部输入

MVP 不在处理单元内部实现旋转因子 ROM 或实时生成功能。

小型 ROM 本身未必复杂，但将其纳入处理单元后，必须同时决定：

- 支持的 FFT 规模；
- 系数数量与量化方式；
- 地址生成方式；
- ROM 读延迟；
- 系数与 `A、B` 的时序对齐；
- 同步读或异步读；
- 处理单元是否仍可接受任意 `W`。

这些问题不会直接增强本轮算术数据通路的工程闭环，却会将处理单元与特定 FFT 系统绑定。因此，MVP 将 `W` 作为外部输入，以保持职责边界清晰。

### 4.4 接口采用 `valid_in/valid_out`

时钟驱动的 V1 使用 `valid_in/valid_out` 表示输入和输出事务有效，不加入 `ready` 或背压机制，并假设下游始终能够接收有效输出。纯组合 V0 没有事务状态，因此核心接口不包含 `valid`；其同步评测包装层可以另行提供有效位。

本轮“流式”仅表示：

- 接口允许连续输入事务；
- 流水版本在稳定状态下以启动间隔 `II=1` 为设计目标，即每个周期最多接收一组新的 `A、B、W`；
- `valid` 必须与对应数据经过相同的流水延迟。

它不表示实现完整的流式 FFT。

加入背压会要求流水线支持暂停、数据保持和恢复，并显著扩大控制与验证状态空间。这些能力对完整系统可能必要，但不属于当前 MVP 的核心问题。

### 4.5 RTL 保持平台无关

RTL 不实例化特定厂商原语，不依赖特定 FPGA 的专有接口，并尽量使用可移植、可综合的 SystemVerilog 描述。

MVP 使用开源 ASIC 工具链完成通用综合、标准单元映射以及布局布线，并在相同工艺库、约束与评测边界下比较 V0 和 V1。具体工具版本、Nangate45 工艺库、SDC、实现流程及结果写入 `05_synthesis_and_ppa_analysis.md`。

这些结果只能表述为当前开源工具链、Nangate45 典型角和指定约束下的实验数据。面积是布局布线后的设计面积；时序是当前寄生参数模型下的静态时序结果；功耗是未注入真实 VCD/SAIF 活动率的 vectorless 估计。它们可以支持同一实验环境内的 V0/V1 相对比较，但不能包装成产品级签核结果，也不能直接外推到其他工艺、其他工具或真实 FFT 工作负载。

## 5. 待比较的微架构

MVP 至少实现两个功能等价的版本：

| 版本 | 结构定位 | 主要用途 |
|---|---|---|
| V0 | 纯组合数据通路的基线版 | 建立最简单的功能和组合逻辑基线 |
| V1 | 三级固定延迟流水版 | 观察明确的三级切分对时序、延迟和资源的影响 |

两版必须使用：

- 相同的数学定义；
- 相同的输入、输出及定点策略；
- 相同的四路分量级饱和接口；
- 可复用的参考模型与测试向量；
- 相同的综合工具、目标器件和可比约束。

V0 与 V1 RTL 使用同一套 17 列测试向量检查四路输出、两路兼容聚合标志及四路分量标志。“功能公平”表示相同有效输入必须产生逐位一致的数值结果和分量标志。

“实现公平”由两个评估包装层建立：`butterfly_comb_eval` 为 V0 添加输入和输出寄存器；`butterfly_pipe_eval` 为 V1 添加等价的外部输入和输出寄存器。两者使用同一工艺库、同一约束口径和同一实现流程。内部流水寄存器属于 V1 的真实微架构成本，必须计入面积、时钟网络和延迟比较。

V1 采用以下三级结构：

1. 第一级计算并寄存 `A+B`、`A-B`，同时寄存与差值属于同一事务的 `W`；
2. 第二级计算并寄存四个实数乘积，同时将 `Y_0` 的宽位和旁路延迟一拍；
3. 第三级完成乘积加减、`Y_1` 舍入、四路饱和，并寄存输出数据和饱和标志。

V1 不支持 `ready`、背压或流水暂停。无效输入拍形成气泡并逐级传播，不压缩事务间隔。若一组输入在第 `t` 个上升沿以 `valid_in=1` 被接受，则对应输出在第 `t+2` 个上升沿更新且 `valid_out=1`。因此，按输入采样沿到输出有效沿的间隔计，V1 固定延迟为 2 个周期，启动间隔为 `II=1`。

该结构的评测结果由 `05_synthesis_and_ppa_analysis.md` 记录。若后续继续切分或重构，必须创建新版本，不得静默改变 V1 的既定定义。

## 6. 评价指标

本项目不使用单一“性能”概念，而分别记录以下指标：

| 指标 | 含义 |
|---|---|
| 功能正确性 | RTL 是否与位精确参考模型一致 |
| 最大时钟频率 `F_max` | 在指定工具、器件和约束下估算的最高工作频率 |
| 关键路径 | 限制时钟频率的实际组合路径 |
| 延迟周期数 | 一组输入到对应输出之间经过的时钟周期数 |
| 时间延迟 | 延迟周期数与实际工作时钟周期的乘积 |
| 启动间隔 `II` | 相邻两组输入事务之间允许的最小周期数 |
| 吞吐率 | 稳态下单位时间可处理的输入组数 |
| 逻辑资源 | 映射后的标准单元、组合逻辑及工具报告的等效资源 |
| 寄存器数量 | 流水及数据保持所需的触发器资源 |
| 乘法资源 | 由目标库映射形成的乘法逻辑及其实现成本 |
| 设计与验证复杂度 | 新增状态、边界条件及验证负担 |
| 功耗 | 区分 vectorless 估计与基于真实活动率的分析，并明确证据边界 |

分析时必须说明一个方案在哪个维度改善、在哪个维度退化。例如，流水化可能提高 `F_max`，同时增加寄存器数量和延迟周期数；它是否值得取决于目标吞吐率、时钟要求、资源预算与系统接口，而不能仅根据 `F_max` 判断。

## 7. 明确排除的内容

以下内容不进入本轮 MVP：

- 完整 FFT；
- DIT 与 DIF 双模式；
- Radix-4 或其他基数比较；
- 4 点、8 点或更大规模 FFT；
- 旋转因子 ROM；
- 旋转因子实时生成；
- 存储系统及单端口、双端口存储比较；
- AXI、DMA 或片外接口；
- `ready`、背压及可暂停流水线；
- 乘法器分时复用或其他资源共享结构；
- 多套输入位宽或 Q 格式比较；
- UVM；
- FPGA 上板验证；
- 产品级物理设计签核、流片与硅后验证；
- 多工艺、多 PVT 角和多实现种子的全面收敛；
- 在缺乏真实活动率时宣称工作负载级功耗；
- 将开源 Nangate45 实验结果表述为商业工艺的产品级完整 PPA。

这些内容可以进入后续工作，但不得在 MVP 尚未闭环时作为临时新增功能加入。

## 8. MVP 验收标准

MVP 完成需要同时满足以下条件：

### 8.1 规格与模型

- DIF Radix-2 Butterfly 数学定义明确；
- 定点格式、位宽传播、舍入和溢出行为有独立规格；
- 存在位精确参考模型；
- 同一输入的参考模型与 RTL 输出能够自动比较。

### 8.2 RTL 与验证

- V0 和 V1 均可综合；
- 两版功能等价，差异仅来自微架构和时序；
- 覆盖定向、边界、溢出、随机、连续有效、有效空洞及复位场景；
- `valid_out` 与对应输出数据正确对齐；
- 测试环境能够自动给出通过或失败结果。

### 8.3 综合与比较

- 两版在相同工具、工艺库和可比约束下完成综合与布局布线；
- 保存面积、时序、功耗、关键路径和电气违规报告；
- 分别比较最高验证通过工作点、延迟、`II`、吞吐率、标准单元面积和寄存器成本；
- 所有结果明确注明工具、工艺库、约束和功耗活动率假设；
- 不将开源典型角结果表述为产品级签核 PPA，也不将最高测试通过频率表述为绝对 `F_max`。

### 8.4 工程闭环

- 综合前记录对关键路径和流水效果的初始假设；
- 综合后区分哪些假设得到支持、哪些被反驳；
- 至少完成一次由验证或综合证据驱动的小型修改；
- 修改后重新验证并综合；
- 记录修改带来的收益、代价和仍未解决的问题。

## 9. 留给后续文档决定的事项

以下事项仍由后续文档或实现阶段决定，不能由本文档的概括性表述替代正式决定：

- 舍入、饱和等组合逻辑的具体代码组织方式；
- 是否增加真实 VCD/SAIF 活动率、多实现种子或其他 PVT 角；
- 是否基于当前结果形成新的 V2 微架构。

其中，数值行为写入 `02_fixed_point_spec.md`；微架构与接口时序写入 `03_microarchitecture.md`；验证闭环写入 `04_verification_plan.md`；工具、工艺库、约束与结果写入 `05_synthesis_and_ppa_analysis.md`。

## 10. 初始假设与待验证问题

### 10.1 已建立的工程事实

- 两个 `N` 位有符号数相加或相减，其完整数学结果可能需要 `N+1` 位；
- 流水寄存器可以切分组合路径，但会增加寄存器资源和延迟周期；
- 标准单元映射、布局布线和时序结果依赖综合工具、工艺库、约束与实现策略；
- `F_max`、延迟和吞吐率不是同一个指标。

### 10.2 已由当前实验支持的判断

- 已冻结的三级 V1 有效切分了 V0 的长组合路径；
- 在两版都支持 `II=1` 的前提下，V1 的主要吞吐收益来自更高的可达时钟频率，而不是每周期事务数变化；
- 这一收益以更多流水寄存器、更大的时钟网络和更高的周期延迟为代价；
- 当前 vectorless 功耗结果显示 V1 更低，但缺少真实活动文件，不能将其解释为真实 FFT 工作负载功耗。

具体数值和适用条件以 `05_synthesis_and_ppa_analysis.md` 为准。

### 10.3 结果分析必须回答的问题

1. V0 和 V1 的实际最差建立路径分别经过哪些算术节点？
2. 若加入真实 VCD/SAIF，当前功耗排序是否保持？
3. 若更换实现种子、PVT 角或工艺库，面积与频率收益是否稳定？
4. `F_max` 的变化是否足以抵偿寄存器、延迟和复杂度的增加？
5. 若目标函数改为更低面积、更低延迟或更低功耗，当前选择是否仍然成立？
6. 哪些结论只适用于当前 Nangate45、工具版本和约束，不能直接推广到产品实现？

## 11. 当前设计意图总结

本项目不以“实现一个最高频率的 Butterfly”为目标，而是通过一个边界明确的 DIF Radix-2 复数 Butterfly，完成一次可验证、可综合、可比较、可修订的数字设计闭环。

MVP 主动排除完整 FFT、旋转因子存储、背压、资源共享和平台专有实现，使研究重点保持在：

- 数学运算如何转化为定点 RTL；
- 位宽和数值策略如何影响正确性与资源；
- 实际关键路径如何决定流水边界；
- `F_max`、延迟、吞吐率与资源之间如何权衡；
- 综合证据如何反过来修改设计判断。

最终价值不在于某一个指标达到最大，而在于能够说明：当前设计解决了什么问题、为何选择它、证据是否支持原始判断，以及目标函数改变后设计应当如何改变。
